# 네이버 원문 사진 함께 가져오기

기준일: **2026-11-07 (한국시간)**. 범위: R03 사진 메타·편집, R05 네이버 재편집, R06 직원 운영. 브랜드: 영국유학센터 신촌점.

## 직원 사용법

1. 관리자로 ‘네이버 가져오기’에서 원문을 읽고 초안을 만들거나 기존 초안을 연다.
2. 글에서 사진을 넣을 위치를 클릭하고, 원문 대조 영역의 **네이버 사진 함께 가져오기**를 누른다.
3. 미리보기에서 사용할 사진을 고른다. 한 페이지에 12개씩 보여주며, 페이지를 넘겨도 한 번에 선택할 수 있는 최대 수는 12개다. 이미 본문에 있는 같은 출처 사진은 다시 선택하지 않는다.
4. 필요한 경우 선택한 사진의 공통 사용 근거를 적고 **선택한 사진 추가**를 누른다. 다운로드·WebP 변환·본문 삽입·비공개 저장을 처리한다. 여러 사진은 선택한 원문 순서로 커서 위치부터 들어간다. 원문과 같은 문단별 배치를 자동 복원하는 기능은 아니며 글에서 위치를 조정할 수 있다.
5. 사진별 설명·캡션·사용 근거·대표 사진을 편집하고, 현재 원고 검토와 별도 공개 승인을 진행한다. 출처 주소와 실제 이미지 크기는 자동 기록한다. 다운로드 성공을 사진 내용·사용 권리·학생 공개 동의의 확인 완료로 기록하지 않는다.

중간에 사진을 읽거나 저장하지 못하면 해당 사진과 실패 이유를 표시한다. 성공한 사진은 하나씩 저장되어 남고, 다시 시도하면 이미 들어간 사진을 중복 추가하지 않는다. 미리보기만 보거나 선택 화면을 닫는 것으로 공개 글은 바뀌지 않는다.

## 지원 범위와 저장

현재 지원하는 것은 네이버 본문에 기록된 **`*.pstatic.net`의 HTTPS JPG·PNG·WebP 정지 이미지**다. 학교 사이트 등 외부 호스트의 사진, GIF·SVG·움직이는 이미지·영상은 선택 가져오기 대상에서 제외한다. 허용되지 않는 사진은 직접 파일을 추가하는 기존 기능을 이용한다. 인증 차단·만료·주소 형식 변경·손상 파일은 실패로 표시한다.

다운로드는 네이버 HTML에 기록된 이미지 URL의 파일이며, 카메라 원본이나 별도 고해상도 파일을 찾아 보관하는 기능은 아니다. 원본 응답은 한 장 8MiB 이하, 4천만 픽셀 이하, 긴 쪽 24,000px 이하로 제한한다. HTTP 연결·읽기는 20초 제한을 둔다. 편집기에서 기존 기준인 긴 쪽 1600px·장당 900KB 이하 WebP로 변환한다.

저장은 기존 `cms_media`와 v2 snapshot의 `imageMeta.source`, `rights`, 실제 `width/height`를 사용한다. 새 DB 테이블·마이그레이션·스토리지·Secret은 추가하지 않았다. 임시 원본과 미리보기는 작업 중에만 사용하며, 본문에 연결한 변환본이 사이트의 사진으로 남는다. D1 사진 용량 관리는 기존 운영 방식과 같다.

자동 이미지 OCR·사진 속 학비/조건의 사실 확인·사진 설명 생성·모델로 이미지 전송은 하지 않는다. AI 재편집에는 여전히 텍스트만 제공한다. 사진 추가는 새 원고 버전이며 이전의 사람/AI 검토나 공개 승인을 그대로 상속하지 않는다. 원래 공개본은 별도 승인 전까지 유지한다.

## 서버·브라우저 경계

- 목록: `GET /api/cms/naver/items/{id}/images?sourceHash=...`.
- 파일: `GET /api/cms/naver/items/{id}/images/{index}?sourceHash=...&key=...`.
- 두 경로 모두 관리자 세션이 필요하다. 전체 본문·현재 원문 해시·저장된 사진 번호·정확한 URL 해시를 대조한다. 글의 텍스트가 같아도 사진 목록이 바뀌었다면 예전 선택으로 다른 사진을 내려받지 않는다. 휴지통 글은 차단한다.
- 임의 요청 URL을 받아 내려받지 않는다. 저장된 목록과 허용된 CDN 호스트에서만 읽고, 리디렉션을 따라가지 않는다. 로그인 Cookie·Authorization을 외부로 전달하지 않는다.
- 응답 크기와 실제 스트림 크기를 모두 제한하며 MIME·파일 시그니처·치수를 확인한다. HTML·SVG·위장 파일·과대한 크기와 지원하지 않는 애니메이션은 거절한다.
- 원본 응답은 `private, no-store`, `nosniff`, `noindex, nofollow`다. 미리보기는 변환한 blob URL이고, 공개 글의 사진은 기존 `/media/{UUID}`만 쓴다. 네이버 사진 URL을 공개 본문 이미지로 직접 연결하지 않는다.
- 변환한 미리보기를 재사용하고 순차 처리한다. 화면을 닫거나 페이지를 바꾸면 진행 중인 미리보기를 취소하고, 화면에서 벗어난 비선택 캐시와 blob URL은 해제한다. 추가는 열어 둔 글 ID에 고정하여 다른 글로 이동하는 동안 엉뚱한 글에 넣지 않는다.

## 근거·검증·배포

확인 파일: `cms/server/naver-content.js`의 기존 URL 수집, `naver.js`의 원문/연결, `api.js`의 이미지 업로드·발행 보호, `content.js`의 이미지 메타·검증. 구현: `cms/server/naver-images.js`, `naver-api.js`, `admin/naver-images.js`, `editor.js`, `editorial.js`, `index.html`, `editor.css`, `scripts/prepare_cms_dev.py`.

실제 pedu2 표본 원문의 사진 주소를 확인했고, `postfiles.pstatic.net` 사진 한 개의 정상 TLS 요청에서 HTTP 200, `image/jpeg`, 70,861바이트와 JPEG 시그니처를 관찰했다. 실제 학교·학생 사진을 테스트 게시글로 저장하거나 공개하지 않았다. 자동 검증은 직접 생성한 가상 단색 이미지·격리 D1·가상 계정·네이버 응답만 사용한다.

| 검증 | 확인 범위 |
|---|---|
| `node tests/check_naver_images.mjs` | 6개. 호스트·형식·치수·스트림 크기·리디렉션·원문/사진 변경·권한·비공개 다운로드·정상 발행 보호·휴지통 |
| `python3 tests/check_naver_images_browser.py` | 5개. 실제 Chromium의 선택·페이지·12개 제한·PNG/WebP 변환·중복·부분 실패와 재시도·본문/출처 보존·독립 공개 승인·JS 없는 공개 HTML |
| `node tests/check_naver.mjs` | 기존 13개 |
| `node tests/check_codex_review.mjs` | 기존 7개 |
| `python3 tests/check_cms.py` | 기존 14개 |
| `python3 tests/check_cms_browser.py` | 기존 9개 |
| `node tests/check_seo.mjs` | 기존 11개 |

위 검증 **총 65개가 통과**했다. 커밋에는 해당 R번호와 검증 범위를 연결한다. esbuild 0.17.19의 CMS 함수 번들과 JS 구문·공백 검사도 수행한다. 화면은 320/390/768/1440px에서 확인하며 브라우저에서 pstatic 호스트로 직접 이미지 요청이 나가지 않는 것도 검사한다.

재현: `CMS_NAVER_IMAGES_UI_FIXTURE=1 node tests/check_naver_images.mjs`로 8799 포트를 유지한 뒤 `python3 tests/check_naver_images_browser.py`를 실행한다. 기존 CMS UI 회귀는 `node tests/serve_cms_fixture.mjs` → `python3 tests/check_cms.py` → `python3 tests/check_cms_browser.py` 순서다. 도구 설치는 [기존 구현 기록](SEO_IMPLEMENTATION.md)을 참고한다.

서버 파일 읽기·검증, 직원 UI·변환·삽입, 운영 안내를 논리 단위로 커밋하고 Cloudflare Pages 체크로 배포를 확인한다. 새 저장 형식이나 외부 서비스가 없으므로 다운로드 UI·엔드포인트를 되돌려도 이미 저장한 기존 WebP와 사진 메타는 유지된다. 운영 CMS 세션으로 실제 사진 가져오기·발행을 실행한 결과와 개발 검증은 구분한다.
