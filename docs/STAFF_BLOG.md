# 직원 블로그 글쓰기 운영

기준일: 2026-11-02 (한국시간) · 공식 명칭: **영국유학센터 신촌점**

## 2026-11-07 네이버 사진 함께 가져오기

네이버 초안을 연 뒤 원문 대조 영역의 **네이버 사진 함께 가져오기**에서 미리보고 선택한다. 네이버에 저장된 JPG·PNG·WebP 정지 사진을 내려받아 기존 크기 기준의 WebP로 바꾸고, 커서 위치에 원문 순서로 삽입·저장한다. 사진 출처·실제 크기는 자동 기록하고, 설명·사용 근거는 사진별로 편집한다. 최대 12개씩 선택하며 중복 사진은 건너뛴다. 공개본은 별도 승인 전까지 유지한다. [지원 범위·실패 복구·검증](NAVER_IMAGES.md)을 참고한다.

## 2026-11-06 글 삭제·휴지통

관리자는 전체 글 목록의 각 행에서 **삭제**할 수 있다. 확인 후 일반 목록과 공개 사이트에서 내리고 휴지통으로 옮긴다. 상단 **휴지통 → 복구**로 원래 주소·내용·사진을 가진 비공개 초안을 복구한다. 바로 다시 공개하지 않으며, 현재 버전 검토와 공개 승인은 별도다. 직원에게 삭제·복구 권한은 주지 않는다. 삭제 실패 시 완료로 표시하지 않고 기존 버전·사진은 보존한다. [처리 범위·검증·복구 제약](POST_DELETION.md)을 참고한다.

## 2026-11-05 편집·검토 기능 보강

후속 지시로 대표 5개 원고의 내용 검토는 운영자 대신 Codex가 완료했다. [완성 원고·근거·보류 범위](editorial-review/2026-11-06/README.md)를 참고한다. 관리자 ‘네이버 가져오기’에서 **Codex 검토 완료 원고 5개 적용**을 사용할 수 있으며, 이미 있는 글은 개별 적용으로 새 버전을 만든다. 해당 기준본과 원고·원문·검토 기한이 일치하면 사람의 재검토 체크 없이 별도로 공개 승인할 수 있다. AI 검토는 사람 검토로 기록하지 않는다. 아래의 일반 글 관리자 검토 절차는 이 다섯 개의 완료 기준본에 대한 추가 검토 요구가 아니다.

원고 v2에 적용 조건·공식 출처·실제 확인일/범위·다음 확인일·수정 이유·관련 글, 사진 설명/권리·공유 대표 사진·비교 표를 추가했다. 실제 사용법은 `/admin/help.html`, 기술 검증·운영 확인 대기는 [첫 구현 기록](SEO_IMPLEMENTATION.md)을 본다. 아래 초기 구현 기록과 구분한다.

입학 안내·비교 글은 현재 버전의 관리자 사실 확인 뒤 별도로 공개 승인한다. 공개 승인 자체도 새 불변 버전으로 남기므로 승인 후 revision은 한 번 더 증가한다. 같은 공개본 재승인은 멱등 처리한다. 기존 slug와 최초 발행일은 유지한다. 기존 원고/DB를 일괄 변환하지 않았으며, 새 편집기로 수정한 원고는 v2 새 버전으로 저장한다. 구형 편집기가 새 메타를 버리지 않도록 저장 요청을 409로 막을 수 있다. 이 경우 원고를 보관하고 새로고침한다.

원고 JSON은 새 메타와 표를 보존하지만 사진 파일·DB 전체 백업은 아니다. 대표 원고의 내용 검토는 완료했다. 실제 운영자 계정·원격 백업·실제 DB 적용·글 공개·색인은 이번 환경에서 확인하지 못했다.

## 주소와 현재 상태

- 직원 작성: `https://uksinchon.com/admin/`
- 직원 사용 안내: `https://uksinchon.com/admin/help.html`
- 공개 글 목록: `https://uksinchon.com/blog/`
- 개별 공개 글: `/blog/story-{글 UUID}/`
- 사이트맵: `/sitemap.xml` · RSS: `/feed.xml`

작성 화면·서버 API·DB 스키마·공개 글 렌더링을 구현했다. 로컬 Cloudflare 실행기와 영구 저장 D1 에뮬레이션으로 검증했으며, 운영자가 제공한 화면에서 D1 바인딩·설정키 저장 후 첫 관리자 등록 화면 진입까지 확인했다. 첫 관리자 생성과 실제 직원 운영은 아직 확인 전이다. 배포 성공과 실제 직원 운영 시작은 구분한다. DB가 없으면 관리 화면에 연결 안내를 표시하고 저장·로그인·발행을 활성화하지 않는다. 실제 직원 계정과 실제 학교 글은 아직 등록하지 않았다.

## 처음 한 번: 운영자 연결

현재 실행환경에는 Cloudflare 계정/API 인증이 없어 DB 생성·바인딩을 직접 실행할 수 없다. 다음은 운영자가 로그인한 Cloudflare에서 해야 하는 설정이다. 메뉴 위치는 화면에 따라 달라질 수 있으므로 실제 화면을 보고 진행한다.

1. 기존 Cloudflare 계정에서 **D1 데이터베이스**를 만든다. 이름 예: `uksinchon-cms`.
2. 기존 Pages 프로젝트 **uksinchon**에 D1 바인딩을 추가한다. 변수 이름은 정확히 **`CMS_DB`**, 대상으로 방금 만든 DB를 선택한다. 운영 배포에 연결한다. 테스트 배포를 운영 DB와 공유하지 않는다.
3. `/admin/` 화면의 ‘이 기기에서 설정키 만들기’를 눌러 키를 만든다. 이 키를 Pages 프로젝트의 암호화된 환경 변수/비밀 값 **`CMS_SETUP_TOKEN`**에 저장한다. 공개 코드·URL·채팅에 붙이지 않는다. `CMS_LOCAL_DEV`는 운영에 설정하지 않는다.
4. 저장한 설정이 적용되도록 **최신 커밋으로 다시 배포**한다. 예전 코드의 배포를 재시도하지 않도록 커밋을 확인한다.
5. `/admin/`을 새로고침한다. DB와 키가 연결되면 첫 관리자 양식이 나온다. 설정키·관리자 표시 이름·이메일·비밀번호(12자 이상)를 넣는다. 여기서 테이블을 자동 생성하므로 SQL을 수동 입력할 필요는 없다.
6. 첫 관리자가 만들어지면 초기 설정은 잠긴다. 로그인 확인 후 `CMS_SETUP_TOKEN`을 운영 변수에서 제거해도 기존 계정은 정상 동작한다. 키를 제거했으면 다시 배포해 반영한다. 관리자 로그인 정보는 운영자가 안전하게 보관한다.
7. ‘직원 계정’에서 직원별 계정을 만든다. 임시 비밀번호는 직원에게 별도로 전달한다. 직원은 첫 로그인 때 새 비밀번호로 바꾼다.
8. 직원 테스트 계정으로 초안·사진·검토 요청 → 관리자 승인 → 공개 URL 확인을 한 번 수행한다. 테스트 글은 내려두고 실제 글 작성을 시작한다.

Cloudflare Pages Functions와 D1을 사용하며, 실제 요금·무료 사용량·알림 한도는 계정에서 확인한다. 외부 AI·이메일 발송·유료 CMS 구독은 필요하지 않다. 사진도 현재 D1에 저장하므로 미디어 규모가 커지면 R2 같은 별도 저장소로 확장한다. 이 작업에서 외부 공식 가격표나 요금제 한도를 재확인했다고 주장하지 않는다.

## 직원의 매일 사용법

1. `/admin/`에 로그인 → **새 글 쓰기**.
2. 제목과 본문을 작성한다. 소제목·굵게·목록·인용·링크·사진을 쓸 수 있다. 사진을 붙여넣거나 ‘사진 추가’로 올린다. JPG·PNG·WebP를 긴 쪽 최대 1600px WebP로 변환한다. 한 번에 최대 12장, 변환 후 한 장 900KB 이하로 받는다. 애니메이션·SVG·영상·PDF 업로드는 지원하지 않는다.
3. 카테고리를 고른다. 요약은 선택이며 비워두면 본문 앞부분을 사용한다. 공식 자료 URL과 정보 확인일을 필요에 따라 기록한다.
4. 잠시 멈추면 공동 DB에 저장한다. 화면을 닫기 전 **저장 완료**를 확인한다. 작성하다 로그아웃하거나 목록으로 돌아갈 때도 저장을 마친다.
5. **저장 후 미리보기**로 읽어본다. 팝업이 차단되면 브라우저에서 허용한다.
6. **검토 요청하기**를 누른다. 관리자 글 목록에 ‘검토 요청’으로 표시되며 메일·메신저 알림은 없다.

학생 개인정보, 고객 대화·성적표, 내부 전용 메일·가격표 원문, 사용 권한 없는 사진은 게시하지 않는다. 가격·입학 조건·비자·자격 정보는 근거와 적용 시점을 확인한 뒤 공개한다. 작성자 표시 이름은 공개 글에 노출된다.

## 관리자 공개와 수정

- 관리자는 모든 직원 글을 볼 수 있고 직원은 자기 글만 볼 수 있다.
- 글 목록에서 검토 요청을 골라 본문·사진·근거·조건을 확인한 뒤 **이 버전 공개 승인**을 누른다.
- 공개 글의 초안을 수정해도 기존 승인본은 유지된다. 새 승인을 해야 내용이 바뀐다. URL은 고정이다.
- **공개 내리기**는 공개 URL을 404로 전환하고 해당 글의 사진도 비공개로 바꾼다. 브라우저나 외부 서비스에 이미 복제된 정보까지 회수하는 기능은 아니다.
- ‘수정 이력’의 예전 내용을 불러오면 새 버전으로 저장한다. 기존 이력은 삭제하지 않는다.
- 계정 사용 중지·임시 비밀번호 재설정은 기존 로그인 세션도 해제한다. 관리자 계정 자체의 분실 복구·이메일 비밀번호 찾기는 초기 범위에서 구현하지 않았다.

## 저장 실패·동시 수정

인터넷이나 서버에 문제가 있으면 저장 완료로 표시하지 않는다. **현재 원고 파일로 보관**하면 JSON 원고를 내려받는다. 같은 글에서 **보관한 원고 불러오기**로 새 버전으로 복구할 수 있다. 사진 파일·다른 글·사용자·DB 전체의 백업은 아니다.

두 창에서 같은 버전을 수정하면 늦게 저장한 쪽을 409 충돌로 막는다. 현재 원고를 보관한 뒤 최신 글을 열고 필요한 부분을 합친다. 자동 공동 편집 기능은 없다.

## 실제 데이터 위치와 백업

- 운영 글·사용자·사진·버전: Cloudflare에서 연결한 **D1 DB**. 로컬 가격 관리 DB와 별개다.
- 원본 편집 코드: `admin/` · 서버: `cms/server/` · Pages 경로: `functions/`.
- 로컬 검증 데이터: `.wrangler/cms-test/` 또는 개발 시 지정한 persist 경로. `.gitignore`로 제외한다.
- 가격 관리 앱 `price_manager/`, 가격 DB, 원본 PDF·메일·백업은 읽거나 수정하지 않으며 공개 커밋 대상이 아니다.

운영 DB 백업은 Cloudflare D1의 내보내기/복구 기능으로 관리한다. 제공 복구 기간과 요금제 조건은 실제 계정에서 확인한다. 인증된 CLI가 있는 별도 운영 환경에서는 `wrangler d1 export <DB이름> --remote --output <비공개 백업 경로>`를 사용할 수 있다. 비밀번호 해시·비공개 초안·사진이 포함되므로 공개 Git이나 사이트 디렉터리에 백업을 두지 않는다. 운영 DB의 원격 내보내기·복원을 이번 작업에서 실행하지 않았다.

## 기술 구조와 제한

- 세션: 해시로 저장한 무작위 토큰, HTTPS HttpOnly·SameSite 쿠키, 8시간 만료.
- 비밀번호: Web Crypto PBKDF2-SHA256 100,000회와 사용자별 salt. 계정별 실패 제한과 IP 단위 시도 제한을 둔다.
- 쓰기 API: 같은 Origin, JSON 요청, 세션·역할·소유권·버전 확인.
- 본문: Quill Delta에서 허용한 서식·자체 사진 참조만 저장한다. 서버가 텍스트·속성을 이스케이프해 HTML을 생성한다. 임의 HTML·스크립트·외부 이미지 임베드를 실행하지 않는다.
- 사진: 본문과 별도 DB 저장. 공개 승인본에 포함된 사진만 익명 접근을 허용한다.
- 승인본: `published_revision`으로 불변 저장 버전을 가리킨다. 최신 초안을 그대로 노출하지 않는다.
- 검색: 공개 글을 서버 HTML로 제공하며 제목·요약·canonical·BlogPosting과 사이트맵·RSS를 생성한다. 초안·관리 화면·미리보기는 검색 제외한다. 실제 구글 색인·AI 인용은 별도 확인 사항이다.
- 기존 홈페이지·약대·설명회·미리보기·Meta 픽셀 설정은 유지한다. 첫 승인 글이 있으면 기존 홈에 블로그 링크를 표시하며, 빈 블로그와 DB 연결 전에는 해당 입구를 숨긴다. 새 관리 화면과 블로그에는 Meta 코드를 추가하지 않았다.
- 예약 발행, 댓글, 태그 관리, 일괄 내보내기, 원격 알림, AI 자동 글쓰기, 전체 DB를 UI에서 복원하는 기능은 아직 없다. 글 삭제·복구는 관리자 휴지통으로 제공하며 원고를 물리 삭제하는 UI는 없다.
- 원고는 6만 자, 최대 4천 Delta 작업, 출처 15개까지 받는다. 이력 목록은 최근 100개를 표시하며 이전 데이터 자체를 삭제하지 않는다.
- `scripts/package_site.py`의 기존 ZIP은 약대·미리보기 등 정적 파일용이다. CMS 운영 배포는 GitHub의 Functions 코드와 D1 연결을 함께 사용한다. 정적 ZIP만 업로드해서 공동 작성 기능이 생기지 않는다.

## 개발·검증 재현

운영 DB가 아닌 로컬에서만 실행한다. Node·Python·Wrangler·Quill 정적 파일과 브라우저 검증용 Playwright/Chromium이 필요하다.

```bash
python3 scripts/prepare_cms_dev.py
npx wrangler@4.156.1 pages dev .wrangler/dev-public --ip 127.0.0.1 --port 8791 --d1 CMS_DB --binding CMS_LOCAL_DEV=true --binding CMS_SETUP_TOKEN=local-test-setup-key-not-for-production-32 --persist-to .wrangler/cms-test --compatibility-date 2026-10-30
python3 tests/check_cms.py http://127.0.0.1:8791
python3 tests/check_cms_browser.py http://127.0.0.1:8791
```

테스트의 이메일·암호·글·사진·설정키는 가상 로컬 데이터다. 테스트 스크립트는 loopback 주소만 받으며 운영에 실행하지 않는다. 라이브러리는 Quill 2.0.3을 자체 제공하며 라이선스는 `admin/vendor/QUILL-LICENSE.txt`에 있다. Wrangler는 로컬 도구이며 운영 서버에서 Node 프로세스를 계속 돌리는 방식이 아니다.

## 후속 Codex 작업

‘직원 계정을 추가하는 방법을 안내해줘’, ‘이 검토 요청 글을 공개 전에 확인해줘’, ‘글 목록을 홈에 연결해줘’와 같이 이어간다. 운영 데이터 확인에는 로그인과 DB 권한이 필요하다. 관리자의 승인 버튼을 대신 누르거나 외부 메시지를 발송한 것으로 가정하지 않는다. 이 문서를 먼저 확인하고 운영 DB·로컬 검증 DB·기존 가격 DB를 구분한다.

## 검증 결과 (가상 로컬 데이터)

- 실제 Wrangler + 영구 로컬 D1 통합 검증 14개 통과: 초기 설정, 권한·CSRF, 직원 계정, 초안·사진 비공개, 관리자 승인, 공개본 보존, 충돌, 버전 복구, 공개 내림, 계정 중지.
- 실제 Chromium 화면 검증 9개 통과: 관리자·직원 로그인, 임시 비밀번호 변경, 본문·사진 등록과 1600px 변환, 320~768px 화면, 재조회, 비공개 미리보기, 공개 승인, 수정본 분리, 저장 실패 후 파일 복구.
- 기존 픽셀 검증 12개 통과: 실제 Meta 이벤트를 전송하지 않고 기존 동작 유지 확인.
- 추가로 로그인 실패 제한·성공 후 제한 초기화, 첫 공개 글에 따른 홈 입구, 서버 재시작 후 데이터 유지, DB 미연결 처리, 잘못된 날짜 거부를 확인했다.
- 운영 DB 바인딩과 첫 관리자 등록 화면은 사용자 제공 화면으로 확인했다. 실제 직원 계정·원격 백업 복원·실제 검색 색인은 확인 전이다.

개발 테스트에는 Pillow도 필요하다. 직원은 설치 없이 브라우저로 이용한다.


## 초기 설정키를 잃어버린 경우

Cloudflare Secret은 저장 후 원래 값을 다시 읽을 수 없다. 첫 관리자 등록 화면의 **‘설정키를 잃어버렸나요?’ → ‘새 설정키 만들기’**에서 새 키를 만든다. 새 키는 현재 기기에서만 생성하며 Cloudflare의 Secret을 자동으로 바꾸지 않는다.

1. ‘새 키 복사’ 또는 ‘키 파일로 보관’을 사용한다. 새 키는 관리자 양식의 초기 설정키 칸에도 들어간다.
2. 다른 탭에서 Cloudflare의 기존 `CMS_SETUP_TOKEN` Secret 값을 새 키로 교체하고 저장한다.
3. 최신 Production 배포를 다시 실행한다.
4. 완료되면 **키를 만든 관리자 탭을 닫거나 새로고침하지 않고** 관리자 정보를 입력해 등록한다. 별도 새로고침 없이 다음 등록 요청이 새 서버 설정을 사용한다.

키를 만든 탭을 닫았다면 보관 파일의 값을 초기 설정키 칸에 넣을 수 있다. 새 키만 만들고 Cloudflare 값을 바꾸지 않으면 등록할 수 없다. 이 기능은 기존 관리자 비밀번호 재설정이나 등록 완료 후의 관리자 추가 경로가 아니다. 성공하면 화면의 키 입력값을 비운다.

분리된 브라우저 대역으로 키 생성·복사 대안·파일 보관·모바일 화면·설정값 불일치 차단·교체 후 동일 탭 등록·성공 후 값 제거를 확인했다. 실제 운영 Secret은 읽거나 변경하지 않았다.
