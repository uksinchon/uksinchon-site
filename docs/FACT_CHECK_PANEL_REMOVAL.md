사용자가 글 작성·발행 시 **공개 전 사실 확인** 메뉴와 ‘출처와 본문’, ‘적용 조건·예외·시점’, ‘개인정보와 사진 사용 근거’의 세 체크 항목을 삭제하도록 지시했다. 기준 코드는 `e53f0d5`, 구현·검증 커밋은 **`d4a96a3` (R02/R03/R06)**다.

## 조사·선택·변경

- `admin/index.html`에서 해당 section·설명·세 체크박스·기록 버튼·상태 안내를 실제로 제거했다. 단순히 숨기는 방식이 아니다.
- `admin/editor.js`, `admin/editorial.js`에서 없어진 요소에 접근하던 초기화·체크 초기화·상태 갱신·클릭 핸들러를 제거했다. 새 글 열기·기존 글 재조회·수정·발행 시 요소 접근 오류가 나지 않아야 한다.
- `cms/server/publication.js`, `cms/server/api.js`에서 일반 글의 발행 시 별도 사실 확인 기록을 필수로 요구하던 조건을 제거했다. 메뉴만 지우면 안내·비교 글이 계속 발행 오류를 내므로 화면과 서버를 함께 바꿨다.
- `cms/server/content.js`의 공식 자료·적용 대상·확인 날짜·대조 범위 입력 검증은 별도 항목으로 유지한다. 사용자 요청은 해당 체크 메뉴의 삭제이며 모든 입력·출처 검증의 제거가 아니다.
- 기록이 없는 새 공개본의 `publication.factCheck`는 `null`이다. 메뉴를 없애는 대신 자동 체크하거나 사람의 검토가 끝났다고 기록하지 않는다. 그런 글에는 공개 페이지의 ‘자료 확인’ 검토자 영역이 생성되지 않는다.
- 기존 원고·과거 검토 이벤트·AI/사람 구분·실제 검토 증명은 삭제하지 않는다. 네이버 가져오기에서 별도로 이루어지는 원문 대조와 Codex 증명의 유효성 검사는 유지한다. 호환용 사실 확인 API는 해당 흐름과 과거 도구를 위해 남지만 일반 직원 글쓰기 화면에서는 호출하지 않는다.
- 직원 본인 글 권한·명시적 발행 확인·불변 공개본·초안 분리·수정 이력·공개 내리기·휴지통은 유지한다. 자료 확인 메뉴를 지웠다고 대기 원고를 자동 공개하지 않는다.

가장 작은 UI 숨김만으로는 기존 서버 차단이 남는다. 자동 확인 이벤트를 만드는 대안은 수행하지 않은 검토를 했다고 표시한다. 따라서 메뉴·연결 코드·발행 필수 조건을 함께 제거하고, 실제 존재하는 이전 기록만 보존하는 방식을 선택했다.

## 검증 기준

1. 새 글·기존 글·수정 글에서 `fact-review-panel`, 세 `fact-check-*`, `record-facts`, `fact-review-state`가 편집기 DOM에 존재하지 않는다.
2. 자료 입력을 갖춘 안내·비교 글이 별도 `/factcheck` 호출 없이 직접 발행·수정 발행된다. 발행 메타에 가짜 검토자·날짜가 생성되지 않는다.
3. 실제 남아 있는 과거 검토 기록과 유효한 Codex 증명은 정확한 검토 주체로 표시한다. 네이버 원문이 바뀌거나 증명이 만료되면 그 기존 처리 규칙을 따른다.
4. 직원/관리자 소유권·이전 revision·Origin·공개본 보존·사진 출처 자유 입력·표/메타·원고 보관 복구·320/390/768/1440px 화면 회귀를 확인한다.

검증은 로컬의 가상 직원·원고·출처·이미지로만 수행한다. 운영 글이나 실제 학생 자료를 테스트에 사용하지 않는다. 코드 배포 체크 성공과 실제 운영 계정 발행 검증을 구분한다.

## 데이터·배포·복구

URL·slug·원고/이미지 저장 모델·기존 날짜를 변경하거나 운영 DB를 일괄 수정하지 않는다. 데이터 변환·마이그레이션·리디렉션은 필요하지 않다. 서버·화면 변경과 검증을 하나의 기능 커밋으로, 안내·운영 기록은 별도 문서 커밋으로 분리한다.

복구 시 기능 커밋을 되돌리고 함께 재배포하면 메뉴와 기존 필수 조건이 복원된다. 이번 변경 이후 검토 기록 없이 발행된 글도 자동으로 내려가지는 않는다. 복구 후 그 글을 다시 발행할 때 예전 체크 절차가 요구될 수 있으므로 해당 정책 복구의 영향을 기록한다. 과거 원고나 이력을 일괄 삭제·수정하지 않는다.
