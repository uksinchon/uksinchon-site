# 상담신청 게시판

기준일: 2026-11-09 (한국시간)

## 주소

- 고객용 신청서: `https://uksinchon.com/counsel/` (개인정보 보호정책: `/counsel/privacy.html`)
- 관리자 게시판: `https://uksinchon.com/admin/counsel.html` · 글쓰기 관리 화면 상단의 **상담신청 게시판** 버튼

## 접수 흐름

고객이 신청서를 제출하면 두 곳으로 동시에 보낸다.

1. **메일**: 기존 Formspree 폼(`mjkpjdka`, Shinchon Counsel Form). 기존과 같다.
2. **게시판**: `/api/cms/counsel/submit` → 글쓰기 DB(`CMS_DB`, D1)의 `cms_counsel` 테이블.

둘 중 하나만 성공해도 고객에게 접수 완료를 보여준다. 게시판 저장이 실패해도 메일은 받는다. 테이블은 첫 접수 때 자동으로 만든다(기존 테이블은 바꾸지 않음).

## 게시판 사용

- 관리자 계정만 볼 수 있다. 직원(작성자) 계정과 비로그인은 차단한다.
- 상태: 신규 → 상담중 → 완료, 스팸. '전체'에는 스팸이 빠진다.
- 상세 화면에서 상태와 상담 메모를 저장한다. 마지막 수정자와 시각을 남긴다.
- 이름·휴대폰·이메일로 검색한다. 30건씩 쪽으로 나눈다.
- 삭제는 되돌릴 수 없다. 메일 사본은 남는다.

## 보호 장치

- 같은 사이트(uksinchon.com)에서 보낸 JSON 요청만 받는다.
- 숨은 칸(`_gotcha`)을 채운 자동 등록은 저장하지 않는다.
- 같은 IP에서 15분에 10건을 넘으면 잠시 막는다.
- 신청서에 있는 항목만 저장하고 길이를 제한한다. 화면 표시는 모두 텍스트로 넣어 HTML이 실행되지 않는다.

## 검증

로컬 Cloudflare 실행기(wrangler pages dev)와 별도 로컬 D1에서 브라우저로 19개 항목을 확인했다. 메일 발송이 실패해도 접수 완료와 게시판 저장, 스팸봇·외부 사이트·연락처 없는 요청 차단, 관리자 탭 표시, 목록·상세·상태·메모 저장·검색·삭제, 직원·비로그인 차단, 휴대폰 화면 가로 넘침 없음. 운영 DB와 실제 고객 정보는 사용하지 않았다.
