# Meta 픽셀과 리타겟팅 준비

## 현재 상태

픽셀 ID가 제공되지 않아 `assets/meta-pixel-config.js`의 `enabled`는 `false`, `pixelId`는 빈 문자열이다. 이 상태에서는 Meta 스크립트·쿠키 선택 화면·방문 이벤트를 만들지 않는다. **연결 준비와 실제 방문 정보 수집은 다르다.** 실제 픽셀이 설치·활성화됐다고 보고하지 않는다.

홈페이지와 약대 상담 페이지에 공통 로더를 연결했다. ID를 연결하면 방문자가 허용한 경우에만 Meta 라이브러리를 불러오고 `PageView`를 보낸다. 거부와 허용 버튼을 제공하고, 이후 ‘광고 쿠키 설정’에서 변경할 수 있다. 선택값만 해당 픽셀/안내 버전과 함께 브라우저에 최대 180일 저장한다. 저장을 사용할 수 없으면 현재 페이지 안에서만 선택을 유지한다.

## 픽셀 ID 준비

1. 신촌점이 관리할 Meta 비즈니스 계정으로 이벤트 관리자에 들어간다: `https://business.facebook.com/events_manager2/`.
2. 기존 웹 데이터 소스(픽셀/데이터세트)가 있으면 해당 소스의 설정에서 픽셀 ID를 확인한다. 없으면 웹 데이터 소스를 새로 만든다. 메뉴 이름은 계정 화면에 따라 다를 수 있다.
3. 사이트 연결 주소는 `https://uksinchon.com/`이다. 숫자로 된 **픽셀 ID만** Codex에 전달한다. 비밀번호·액세스 토큰을 채팅에 보낼 필요는 없다.
4. 광고에 사용할 신촌점 계정에 해당 픽셀/데이터세트 사용 권한을 연결한다. 스터디그룹 소유 픽셀에만 방문자가 쌓이는 구조인지, 신촌점이 실제 사용할 수 있는 자산인지 구분한다.

설치는 그 이후의 방문부터 기록하며, 설치 전 방문자를 소급해서 만들지는 못한다. 방문자의 허용 여부, 브라우저 설정 및 차단 확장 기능 등에 따라 모든 방문이 기록되는 것은 아니다. 리타겟팅 광고의 실제 제공 여부는 Meta 계정·정책·대상 규모 등 조건에도 영향을 받는다.

## 연결과 확인

확인된 ID를 다음 설정에 넣고 `enabled: true`로 변경한다.

```js
window.UK_META_PIXEL_CONFIG = Object.freeze({
  enabled: true,
  pixelId: '실제로 발급된 숫자 ID',
  consentVersion: 1
});
```

실제 ID를 활성화할 때 Meta 데이터 소스의 **자동 고급 매칭·자동 이벤트 설정을 끈 상태인지 확인한다.** 이 사이트는 추가로 원문서의 `fbq('set', 'autoConfig', 'false', PIXEL_ID)`를 `init` 앞에 호출하고, 매칭용 이름·이메일·전화번호 객체를 제공하지 않는다. 자체 연동 코드는 상담 양식의 이름·학력·영어 수준·자유 입력을 읽거나 Meta에 전달하지 않는다. 아직 계정 설정을 확인하지 못했으며 코드의 옵션을 계정 설정 확인의 대체로 보고하지 않는다. 방문 이벤트에는 Meta가 URL·기기·광고 식별 정보 등을 처리할 수 있음을 선택 화면에 안내한다. 실제 운영 사업자의 개인정보 안내도 이 처리 방식과 맞춰 관리한다.

광고에 필요한 최소 이벤트인 `PageView`만 보낸다. ‘상담 내용 만들기’, 복사, 카카오톡 버튼 클릭을 `Lead`나 상담 접수 완료로 기록하지 않는다. 사이트 양식과 카카오톡 실제 수신 사이에 완료 확인 연동이 없기 때문이다.

설정 반영 후 공개 사이트에서 허용/거부/철회 흐름을 확인한다. 이벤트 관리자 테스트 이벤트나 Meta Pixel Helper로 올바른 ID의 `PageView` 수신을 확인한다. 코드 테스트에 가상 ID나 Meta 스크립트 대역을 사용한 결과는 실제 계정 수신 검증과 구분한다.

이벤트가 쌓이면 Meta 광고 관리자에서 웹사이트 맞춤 타겟을 만들 수 있다. 예를 들어 전체 방문자와 URL에 `/pharmacy/`가 포함된 방문자를 구분한다. 기존 방문자의 문의 완료 여부까지 구분하려면 별도 완료 확인 설계가 필요하다.

## 구현과 범위

- 설정: `assets/meta-pixel-config.js`
- 동의 선택·라이브러리 로드·PageView: `assets/meta-pixel.js`
- 선택 화면: `assets/meta-pixel.css`
- 예상하지 못한 경로·쿼리·해시가 있는 URL은 방문 이벤트를 생략해 URL에 들어간 미확인 정보를 전달하지 않는다. 정상 캠페인 태그와 Meta 클릭 식별자만 제한된 문자 형식으로 허용한다.
- 철회는 Meta의 `consent/revoke`를 호출하고 이 도메인의 `_fbp`·`_fbc` 쿠키를 만료한다. 이미 보낸 정보를 소급 취소하거나 Meta 도메인의 쿠키를 이 사이트에서 삭제할 수 있다고 주장하지 않는다. 상담 입력을 잃지 않도록 강제 새로고침하지 않는다.
- JavaScript 비사용 시 광고용 추적 이미지(`noscript` 픽셀)를 넣지 않는다.
- `약대_상담페이지_바로열기.html` 단독 미리보기에는 픽셀 로더를 넣지 않는다.
- 기존 Cloudflare 호스팅의 Web Analytics 설정은 이 픽셀 선택과 별도이며 변경하지 않았다.

## 검증

`python3 scripts/check_meta_pixel.py`로 가상 ID·Meta 라이브러리 대역을 사용해 실제 계정으로 이벤트를 보내지 않고 검증한다. 12개 항목이 통과했다: 비활성 상태, 잘못된 ID 차단, 허용 전·거부 후 무요청, 명시적 허용의 초기화·단일 PageView, 상담 입력·가짜 Lead 없음, 동의 철회·쿠키 만료·입력 보존, 미확인 URL 차단, 정상 캠페인 태그, 브라우저 저장 거부, 라이브러리 다운로드 중 철회, 홈→약대의 동의 유지, 만료·안내 버전 변경·미래 시각 기록의 재동의다. 실제 Meta 계정의 이벤트 수신은 픽셀 ID 연결 후 별도로 확인해야 한다.
