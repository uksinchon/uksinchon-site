확인일: **2026-11-18 한국시간** · 관련 로드맵: **R02(발행·이력), R03(직원 입력), R06(검증·배포)**

사용자가 ‘이번에 대조한 조건과 자료의 범위’ 같은 질문 없이 발행하도록 지시했다. 기준 코드는 `ff092ec`, 구현·검증 커밋은 **`54a719b` (R02/R03/R06)**다. 직전 변경은 체크리스트만 제거했고 서버의 검토 정보 필수 검사는 남아 있었으므로, 필드 하나를 지운 뒤 다른 검토 질문으로 다시 막히는 방식을 피하도록 발행용 검토 정보를 선택 입력으로 정리했다.

## 변경과 판단 근거

- `admin/index.html`, `admin/editorial.js`: 대조 범위 입력·라벨·DOM 참조를 삭제했다. 적용 대상·공식 자료·실제 확인일은 **참고 정보 · 선택**, 수정 이유는 **선택**으로 안내한다.
- 기존 `reviewScope` 값은 편집기에서 다시 질문하지 않고 내부 원고 데이터에 보존한다. 기존 글을 열어 요약·본문을 저장해도 이 값을 지우지 않는다. Codex 검토 원고의 실제 검토 범위·증명도 보존한다.
- `cms/server/publication.js`: 일반 발행은 확인 날짜·대조 범위·적용 대상·공식 자료가 비었다고 차단하지 않는다. `requiresFactCheck`나 안내/비교 유형 자체도 추가 필수 질문을 만들지 않는다.
- `cms/server/api.js`: 공개 글 재발행 시 수정 이유·범위 입력을 강제하던 조건도 제거했다. 실제 내용 변화에 따른 수정일과 발행 이력은 이유 입력 여부와 독립적으로 기존 서버 규칙대로 기록한다.
- `cms/server/content.js`: 호환용 사실 확인 API의 대조 범위 필수 검사도 제거해 같은 질문을 다시 발생시키지 않는다. 이 API의 날짜·출처 검증은 실제로 기록을 요청하는 과거 도구를 위해 남아 있으나 일반 작성 화면은 호출하지 않는다.
- `admin/editor.js`: 네이버의 별도 원문 대조를 기록할 때 일반 사실 확인 API까지 자동 호출하던 연결을 제거했다. 원문 대조 자체의 권한·현재 버전·원문 해시 검증은 유지한다. 검토 정보가 비어 있다는 이유로 원문 대조 후 또 다른 질문이 나오지 않는다.

제목·본문·실제 이미지 파일과 글 소유권, 현재 revision·Origin·계정 상태는 유지한다. 선택 입력에 작성한 명백히 잘못된 웹주소나 날짜 형식도 기존 규칙대로 검증한다. 자동으로 검토 범위·출처·확인 날짜를 만들어 채우거나 사람의 검토 완료로 표시하지 않는다.

## 운영·데이터

일반 글은 제목과 본문을 작성한 뒤 **발행하기**, 수정 후에는 **수정 내용 발행하기**를 사용한다. 추가 검토 정보·수정 이유를 비워 두어도 된다. 기존 글의 주소·slug·사진·과거 버전·최초 발행일과 실제 내용 수정일의 의미는 유지한다. 기존 초안을 자동 공개하지 않는다.

서버 검사만 풀고 입력 항목을 남기는 안은 사용자가 계속 필수 질문으로 받아들일 수 있다. 기존 범위 데이터를 삭제하는 안은 원고 이력과 실제 검토 증명을 손상시킨다. 따라서 질문은 제거하고 기존 값은 보존하며, 필요한 추가 정보만 선택으로 기록하는 방식을 택했다. DB 변환·마이그레이션·리디렉션은 필요하지 않다.

복구는 기능 커밋과 화면을 함께 되돌려 재배포한다. 이 변경 후 추가 정보 없이 공개한 글은 자동으로 내려가지 않는다. 예전 발행 규칙을 복원하면 해당 글의 다음 발행 때 과거 필수 정보가 다시 요구될 수 있다. 운영 원고를 일괄 변환하거나 실제로 확인하지 않은 내용을 채우지 않는다.

## 완료 기준

- 일반·안내·비교·사례 글에서 검토 정보가 모두 비어 있어도 직접 발행한다. 수정 이유가 비어 있는 실제 내용 변경도 재발행한다.
- 실제 브라우저에서 대조 범위 입력이 없고, 다른 검토 필드에 손대지 않은 안내 글이 발행된다.
- 기존 범위를 가진 원고를 열고 저장해도 이전 값이 보존된다. 유효한 Codex 원고의 검토 범위와 실제 AI 검토 표시는 유지한다.
- 빈 정보를 검토 완료 메타나 확인 날짜로 만들어 내지 않는다. 원문 변경·만료된 Codex 증명과 다른 사람 글의 접근은 기존대로 차단한다.

검증은 가상 로컬 계정·원고·출처·이미지로 수행하며 코드 배포와 실제 운영 계정 발행 검증을 구분한다. 원격 운영 DB나 실제 학생 원고를 검증용으로 사용하지 않는다.
