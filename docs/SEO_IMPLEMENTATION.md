# SEO·AEO·GEO 첫 구현 기록

기준일: 2026-11-05 (한국시간). 브랜드: **영국유학센터 신촌점**.

사용자가 [진단](seo-audit.md)과 [로드맵](seo-roadmap.md)의 권장 방향 실행을 요청했다. 대표 글 5개의 최종 내용 검토는 **운영자 본인**이 맡는다. 이 기록은 개발 기능·가상 검증·실제 운영 확인·내용 공개를 구분한다.

## 범위와 구조 결정

- R01: 기존 `/blog/story-{UUID}/` 주소·ID 유지. 제목 변경으로 URL을 바꾸지 않는다.
- R02: 기존 테이블·스냅샷을 덮어쓰거나 일괄 변환하지 않는 v2 확장. 공개 승인 시 서버가 만든 메타를 새 불변 버전에 보존한다. 기존 버전은 그대로 남긴다.
- R03: 직원의 적용 조건·공식 출처·사실 확인 입력, 이미지 설명·권리·크기, 안전한 비교 표.
- R04: 서버 HTML·메타·날짜·관련 링크·목록 경계·페이지 canonical 보강.
- R05: 입학·비교·시점 자료·사례·장학금 5유형의 기술 검증과 운영자 검토용 초안 준비를 구분한다.
- R06/R08: 실제 접근·운영 권한이 확인되는 범위만 기록한다. 실제 원고는 운영자 내용 검토 전 공개하지 않는다.
- R07 이후: 대표 글 결과를 확인한 뒤 단계적으로 확대한다. 모든 네이버 글 자동 공개·전체 저장소 이전·SSG 재구축은 첫 범위가 아니다.

## 운영 확인 대기

현재 작업 환경에 Cloudflare D1·WAF·Search Console 인증 권한이 없다. 실제 계정·공개 글 수·봇 로그·GSC 설정/보고서·원격 백업·미디어 사용량은 확인 대기다. 가상 로컬 DB와 실제 운영 DB를 구분하며 Secret 값을 채팅으로 받지 않는다.

기존 운영 데이터를 일괄 수정하는 마이그레이션은 실행하지 않는다. 새 형식은 사람이 편집·승인하는 새 버전에서만 저장하도록 한다. 전체 운영 백업·복구 연습은 수행했다고 표시하지 않는다. 과거 글 일괄 변환·원격 데이터 이전은 백업/복구 확인 전 시작하지 않는다.

## 변경·검증 연결

후속 커밋마다 R번호·달라진 동작·검증 결과·복구 제약을 이 절에 기록한다. 코드 배포 성공과 실제 원고 공개·색인·AI 성과는 별도다.

### R02 — 원고 v2와 불변 공개 승인본

기존 DB 테이블을 유지하며 메타를 버전 snapshot에 추가했다. 공개 승인은 새 버전 하나를 만들고 서버가 발행일·실질 수정일·검토 담당자와 근거 버전을 기록한다. 초안과 과거 승인 버전을 덮어쓰지 않는다. 반환 revision은 새 승인 버전이며 편집기는 승인 후 다시 읽어야 한다. 같은 공개본 재승인은 버전을 추가하지 않는다.

제목/카테고리 변경은 slug에 영향을 주지 않는다. 새 v2 원고를 구형 편집기가 저장해 필드를 버리는 요청은 409로 막는다. 입학 안내·비교 글은 현재 revision의 관리자 사실 확인이 있어야 공개할 수 있다. 확인일은 입력한 실제 확인일이며 저장 시각과 구분한다. 사진 크기는 소유한 WebP 바이트에서 얻는다.

검증: `node tests/check_editorial_model.mjs` 6개, `node tests/check_seo.mjs` 5개 통과. 후자는 격리된 가상 D1/계정만 사용했다. 공개본 보존·현재 버전 검수·위조 날짜 제거·오탈자/실질 변경·재승인·구형 편집기·원본 이력 보존을 확인했다. 운영 데이터 마이그레이션·원격 DB 쓰기는 없었다.

복구: 과거 원고는 이전 버전으로 남는다. v2 쓰기를 시작한 뒤에는 새 형식을 이해하는 호환 API를 유지해야 하며, 모든 새 필드를 버리는 옛 API로 단순 회귀하지 않는다. 전체 운영 DB 복구 검증을 대신한 결과는 아니다.

### R01·R04 — 공개 HTML·주소·검색 메타

글 상세의 초기 HTML에 승인본의 적용 조건·출처·자료 확인 책임·사진 설명·표·관련 글을 출력한다. 가시 수정일·Article/BlogPosting·sitemap lastmod는 같은 승인 메타를 사용한다. 구형 원고에서 실제 내용 수정 시점을 알 수 없으면 날짜를 만들지 않는다. 제목·분류를 고쳐도 기존 글 주소를 유지한다.

일반 목록은 페이지마다 canonical을 유지한다. 카테고리는 안정적인 코드로 연결하며, 기존 한글 라벨 주소를 코드 필터로 308 정규화한다. 페이지 번호와 광고 태그는 보존한다. 필터는 자기 canonical과 `noindex,follow`, 범위를 벗어난 페이지는 404다. 같은 발행 시각은 ID를 보조 정렬 키로 사용한다. 홈의 블로그 링크를 최초 HTML에 표시한다. 프롤로그 모듈·주제 허브의 전체 개편은 아직 하지 않았다.

검증: 공개 글 25개를 12/12/1개로 나누어 링크·canonical·정렬·404를 확인했다. 가상 입학·비교·시점 소식·사례·장학금과 기존 v1 DB 원고를 포함한 `node tests/check_seo.mjs` 11개가 통과했다. 구형 원고를 새 버전으로 승인해도 기존 snapshot과 URL을 유지하며 검토일·수정일을 위조하지 않는 것을 확인했다. 본문·JSON-LD·sitemap 날짜, 사소한 수정, 사실 재확인, 공개 내림과 사진 접근 회수도 확인했다.

기존 게시글의 slug 변경·정적 페이지 주소 이전·www 리디렉션·호스팅 보안 규칙 변경은 하지 않았다. 실제 운영 주소의 403 원인은 확인하지 못했으므로 전역 접근 정책을 바꾸지 않았다.

### R03·R05 — 직원 편집기와 대표 글 검토 준비

직원 편집기에 글 유형·적용 조건·공식/참고 출처·사실 확인 범위·다음 확인일·수정 성격/이유·관련 글을 추가했다. 해당하는 글만 조건 필드를 채운다. 소식·사례 전체에 FAQ나 같은 본문 구조를 강제하지 않는다. 불완전한 출처는 초안으로 보관할 수 있고 공개 전에 주소 완성을 확인한다.

사진마다 설명·캡션·사용 근거·장식 여부·출처를 기록하고 공유 대표 사진을 고른다. 비교 표는 허용된 열/행 구조로 저장하며 엑셀의 데이터 행을 붙여넣고 다시 편집할 수 있다. 모바일의 넓은 표는 표 안에서 좌우로 읽는다. 표·사진·출처 메타는 재조회·미리보기·원고 파일 보관/복구에 포함된다. 사진 파일과 DB 전체 백업은 원고 JSON에 포함되지 않는다.

네이버 재편집을 다시 수행해도 사람이 입력한 적용 조건·공식 출처·확인일·관련 글을 보존하고 공개 승인 증명은 새 초안에 복사하지 않는다. 네이버 원문 대조의 세 항목을 사람이 확인하면 필요한 공식 자료 사실 확인도 함께 기록한다. 공개 승인은 별도다.

관리자 메뉴 **네이버 가져오기 → 먼저 검토할 대표 글 5개 → 대표 5개 검토 초안 준비**를 추가했다. 원문 정리 단계이며 AI를 호출하거나 자동 공개하지 않는다. 새 원문은 비공개 초안으로 만들고 입학·비교·시점 자료·사례·장학금 유형을 지정한다. 이미 연결된 원고는 다시 작성하지 않아 사람의 편집 내용을 보존한다. 실패 항목을 표시하며 같은 기능으로 기존 연결 상태를 확인할 수 있다.

**실제 운영의 대표 원고를 이번 환경에서 생성하거나 검토했다고 표시하지 않는다.** 운영자 로그인 권한이 없어 실제 DB의 초안을 직접 만들 수 없다. 배포 후 운영자가 위 버튼으로 준비하고, 사이트용 재편집·공식 근거·사진 권리를 직접 확인한 뒤 공개한다. 버튼 준비만으로 AEO/GEO 편집이 끝난 것은 아니다. AI 정기 재편집·유료 API·Cron 활성화는 아직 하지 않았다.

### 성능·운영 접근·확대 상태

가상 HTML·그림·표가 있는 로컬 Workers 페이지를 Chromium 390×844, CPU 4배 감속, 네트워크 지연 150ms/하향 200,000바이트/s 설정 요청, 캐시 비활성 상태로 3회 관찰했다. LCP는 540/492/484ms, CLS는 각각 0이었다. 이는 작은 가상 이미지로 만든 **개발 회귀 기준선**이다. 로컬 요청의 TTFB는 11.5~17.4ms였으며 네트워크 설정 효과를 실제 휴대전화 환경과 동일하게 보지 않는다. 실제 학교 사진·긴 원고·운영 CDN의 성능, 현장 CWV·INP는 미측정이다.

운영 공개 URL과 `/api/cms/status`, `robots.txt`는 이번 환경에서 계속 HTTP 403/1010이다. 실제 Googlebot·AI 봇 차단으로 단정하지 않는다. Cloudflare WAF·실제 봇 로그·GSC의 생성형 AI 포함/상속·성과 보고서·원격 백업은 인증 권한이 없어 확인 대기다. robots·학습 허용·CDN 보안·GSC 설정은 바꾸지 않았다.

R06은 **기술 기능 배포와 실제 원고 공개를 구분**한다. 배포 결과는 해당 커밋의 Cloudflare Pages 체크로 확인한다. 실제 대표 5개 원고는 운영자 내용 검토 뒤에 공개하고, 최종 200·GSC 색인/선택 canonical·봇 로그·실제 성능을 별도로 확인한다. R07의 프롤로그/주제 허브 확장, R09 유료 AI/정기 감지, R10 과거 글 확대, R11 저장소 이전은 이 결과 이후다.

## 개발 재현

애플리케이션에 새 외부 구독·빌드 프레임워크·DB 마이그레이션·운영 Secret을 추가하지 않았다. 로컬 검증 도구만 저장소 밖에 설치한다.

```bash
npm --cache /tmp/uksinchon-npm-cache install --prefix /tmp/uksinchon-cms-tools --no-audit --no-fund miniflare@5.20261101.0-beta esbuild@0.25.12
python3 scripts/prepare_cms_dev.py
node tests/check_editorial_model.mjs
node tests/check_seo.mjs
node tests/check_naver.mjs
```

화면 검증은 `CMS_SEO_UI_FIXTURE=1 node tests/check_seo.mjs`를 8796 포트에서 유지한 뒤 `python3 tests/check_seo_browser.py`로 수행한다. 네이버는 `CMS_NAVER_UI_FIXTURE=1 node tests/check_naver.mjs`와 `python3 tests/check_naver_browser.py`를 사용한다. 기존 CMS 회귀는 `node tests/serve_cms_fixture.mjs`를 유지하고 8791에서 기존 Python 검증 두 개를 실행한다. 테스트 서버는 loopback 전용 가상 데이터이며 실제 운영에 실행하지 않는다. Python Playwright·Pillow·Chromium이 필요하다.
