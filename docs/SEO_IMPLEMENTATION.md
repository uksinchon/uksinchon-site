# SEO·AEO·GEO 첫 구현 기록

기준일: 2026-11-05 (한국시간). 브랜드: **영국유학센터 신촌점**.

사용자가 [진단](seo-audit.md)과 [로드맵](seo-roadmap.md)의 권장 방향 실행을 요청했다. 대표 글 5개의 최종 내용 검토는 **운영자 본인**이 맡는다. 이 기록은 개발 기능·가상 검증·실제 운영 확인·내용 공개를 구분한다.

## 범위와 구조 결정

- R01: 기존 `/blog/story-{UUID}/` 주소·ID 유지. 제목 변경으로 URL을 바꾸지 않는다.
- R02: 기존 테이블·스냅샷을 덮어쓰거나 일괄 변환하지 않는 v2 확장. 공개 승인 시 서버가 만든 메타를 새 불변 버전에 보존한다. 기존 버전은 그대로 남긴다.
- R03: 직원의 적용 조건·공식 출처·사실 확인 입력, 이미지 설명·권리·크기, 안전한 비교 표.
- R04: 서버 HTML·메타·날짜·관련 링크·목록 경계·페이지 canonical 보강.
- R05: 입학·비교·시점 자료·사례·장학금 5유형의 기술 검증과 운영자 검토용 초안 준비를 구분한다.
- R06/R08: 실제 접근·운영 권한이 확인되는 범위만 기록한다. 실제 원고는 운영자 내용 검토 전 공개하지 않는다.
- R07 이후: 대표 글 결과를 확인한 뒤 단계적으로 확대한다. 모든 네이버 글 자동 공개·전체 저장소 이전·SSG 재구축은 첫 범위가 아니다.

## 운영 확인 대기

현재 작업 환경에 Cloudflare D1·WAF·Search Console 인증 권한이 없다. 실제 계정·공개 글 수·봇 로그·GSC 설정/보고서·원격 백업·미디어 사용량은 확인 대기다. 가상 로컬 DB와 실제 운영 DB를 구분하며 Secret 값을 채팅으로 받지 않는다.

기존 운영 데이터를 일괄 수정하는 마이그레이션은 실행하지 않는다. 새 형식은 사람이 편집·승인하는 새 버전에서만 저장하도록 한다. 전체 운영 백업·복구 연습은 수행했다고 표시하지 않는다. 과거 글 일괄 변환·원격 데이터 이전은 백업/복구 확인 전 시작하지 않는다.

## 변경·검증 연결

후속 커밋마다 R번호·달라진 동작·검증 결과·복구 제약을 이 절에 기록한다. 코드 배포 성공과 실제 원고 공개·색인·AI 성과는 별도다.

### R02 — 원고 v2와 불변 공개 승인본

기존 DB 테이블을 유지하며 메타를 버전 snapshot에 추가했다. 공개 승인은 새 버전 하나를 만들고 서버가 발행일·실질 수정일·검토 담당자와 근거 버전을 기록한다. 초안과 과거 승인 버전을 덮어쓰지 않는다. 반환 revision은 새 승인 버전이며 편집기는 승인 후 다시 읽어야 한다. 같은 공개본 재승인은 버전을 추가하지 않는다.

제목/카테고리 변경은 slug에 영향을 주지 않는다. 새 v2 원고를 구형 편집기가 저장해 필드를 버리는 요청은 409로 막는다. 입학 안내·비교 글은 현재 revision의 관리자 사실 확인이 있어야 공개할 수 있다. 확인일은 입력한 실제 확인일이며 저장 시각과 구분한다. 사진 크기는 소유한 WebP 바이트에서 얻는다.

검증: `node tests/check_editorial_model.mjs` 6개, `node tests/check_seo.mjs` 5개 통과. 후자는 격리된 가상 D1/계정만 사용했다. 공개본 보존·현재 버전 검수·위조 날짜 제거·오탈자/실질 변경·재승인·구형 편집기·원본 이력 보존을 확인했다. 운영 데이터 마이그레이션·원격 DB 쓰기는 없었다.

복구: 과거 원고는 이전 버전으로 남는다. v2 쓰기를 시작한 뒤에는 새 형식을 이해하는 호환 API를 유지해야 하며, 모든 새 필드를 버리는 옛 API로 단순 회귀하지 않는다. 전체 운영 DB 복구 검증을 대신한 결과는 아니다.
