# 네이버 pedu2 → 신촌점 초안·검수 연동

기준일: 2026-11-02 (한국시간). 직원 CMS 운영 안내는 [STAFF_BLOG.md](STAFF_BLOG.md)를 함께 본다.

## 현재 구현과 활성화 상태

관리자 화면 `/admin/`에 **네이버 가져오기**를 추가했다. 공개 네이버 RSS·본문 읽기, 원문/이력 보관, 중복 방지, AI 요청 연동, 원문 기반 수동 초안, 현재 버전의 휴먼 검수, 별도 공개 승인을 구현했다.

운영 계정의 OpenAI API나 예약 Worker는 이 작업에서 연결하지 않았다. 설정값이 없는 기능은 연결 대기로 표시한다. 운영 관리자 로그인·운영 DB에 실제 네이버 글 등록·실제 AI 모델의 품질·실제 예약 호출·구글 색인·AI 인용은 별도 확인이 필요하다. 첫 관리자 등록이 끝나야 이 메뉴를 사용할 수 있다.

## 원하는 운영 흐름

네이버 게시 → RSS에서 새 글 발견 → 공개 본문 텍스트 별도 읽기 → AI 재편집 초안 → 담당자 수정·원문 대조 → 검수 완료 기록 → 관리자의 공개 승인 → 신촌점 블로그 공개.

검수와 공개 승인은 각각 별도 동작이다. 자동 수집·재편집은 검수 기록과 공개 승인을 만들지 않는다. 기존 직원 직접 작성 흐름도 계속 사용할 수 있다. 초기 버전은 관리자만 네이버 연결·수집·재편집·검수할 수 있으며 연결한 관리자가 초안 담당자로 저장된다.

## 실제 접근 확인

- 사용자 지정 블로그: https://blog.naver.com/pedu2
- RSS: https://rss.blog.naver.com/pedu2.xml
- 2026-11-02 TLS 검증을 유지한 조회에서 RSS HTTP 200, 최근 글 **50개** 확인.
- 표본 최신 글: https://blog.naver.com/pedu2/224462051067
- 해당 RSS 요약은 351자, 공개 본문 추출은 1,794자, 사진 참조 9개였다. HTML 텍스트를 읽었으며 사진 내용·학생 정보의 공개 적합성·학교 조건을 별도로 검증한 것은 아니다.
- 원문 본문은 공개 `PostView.naver`의 `se-main-container` 영역을 읽는다. 접근 차단·본문 형식 변경·구형 편집기·비공개 글은 확인 대기로 남길 수 있다. 로그인·차단 우회는 하지 않는다.
- 실제 자료는 읽기·추출 범위 확인에만 사용했다. 원문 전체나 실제 고객 자료를 공개 Git에 넣지 않았고 실제 사이트에 테스트 글을 공개하지 않았다.

RSS의 잘린 요약을 완전한 글로 간주하지 않는다. 사진은 참조 정보만 기록하며 다운로드·복사·OCR하지 않는다. 원문 사진 속 표·가격·입학 조건은 별도로 확인한다. 자동 추출이 실패하면 원문 텍스트를 직접 넣고 전체 원문과 대조했다는 확인을 남길 수 있다.

## 처음 시작하는 방법

1. 관리자로 `/admin/` 로그인 → **네이버 가져오기**.
2. **새 글 감지 허용**을 켜고 설정을 저장한다. 이 설정만으로 예약 Worker가 설치되지는 않는다.
3. **지금 새 글 확인**을 누른다. 첫 확인은 RSS의 기존 글을 기준 목록으로만 등록하며 과거 50개를 자동 재편집하지 않는다. 이후 처음 발견한 글을 새 글로 처리한다.
4. 먼저 시험할 기존 글 하나의 **원문 보기·보완 → 전체 본문 다시 읽기**를 사용한다. RSS 밖의 글은 개별 주소를 넣어 추가할 수 있다.
5. API 연결 후 **AI 재편집 초안 만들기**를 사용한다. 연결 전에는 **원문 정리 초안 만들기 · AI 없이**로 본문을 준비하고 직접 재편집한다. 후자는 AI 결과로 표시하지 않는다.
6. 초안에서 원문·조건·출처·사진·개인정보를 확인한다. 세 확인란을 체크하고 **현재 버전 검수 완료 기록**을 누른다.
7. 별도로 **이 버전 공개 승인**을 눌러야 게시된다. 본문을 수정하면 검수가 무효화되므로 수정과 저장을 먼저 끝낸다.

사용자용 화면 안내: `/admin/naver-help.html`.

## AI 재편집 연결과 비용

기존 Cloudflare Pages 프로젝트 `uksinchon`의 운영 환경에 다음을 연결한다.

| 설정 | 유형 | 목적 |
|---|---|---|
| `OPENAI_API_KEY` | Secret | OpenAI API 인증 |
| `CMS_REWRITE_MODEL` | 일반 변수 | 운영자가 선택한 사용 가능한 모델 ID |

사용 모델은 Responses API의 structured output JSON schema를 지원해야 한다. 설정 저장 후 최신 버전으로 다시 배포한다. 모델 이름이나 키의 존재를 실제 호출 성공으로 표시하지 않는다. 모델별 권한·속도·정확성은 한 글로 실제 호출해 확인한다. 예시 모델 ID를 계정에서 사용할 수 있다고 가정하지 않는다.

공개 네이버의 제목·본문 텍스트·주소·원문 게시일을 `https://api.openai.com/v1/responses`로 전송한다. `store:false`로 요청하되 이는 제공자의 모든 기록 보관을 끈다는 뜻이 아니다. 실제 데이터 정책은 운영자의 API 계정·제공자 정책에 따른다. 사진이나 내부 가격 DB·고객 상담 메일은 보내지 않는다.

API는 ChatGPT 구독과 별도 사용료가 발생할 수 있다. 모델과 원문·응답 길이에 따라 비용이 달라지므로 연결 전에 공식 가격과 계정 한도를 확인한다. 자동 확인 1회에 대기 글 최대 2개까지 재편집하며 수동 요청은 별도다. AI 오류 글은 자동 반복 요청에서 빼고 관리자 확인을 기다린다. 사용량·청구를 이 사이트가 집계하거나 제한하는 기능은 아니므로 제공자 계정 한도도 설정한다.

## AI 편집 범위

- 핵심 질문에 먼저 답하기, 조건별 소제목·문단·목록, 필요한 질문 답변, 간단한 요약으로 재구성한다.
- 모든 브랜드 표기는 **영국유학센터 신촌점**으로 정규화한다. 원문 확인용 텍스트는 그대로 보존한다.
- 원문의 가격·날짜·자격·예외를 보존하며 가격 환산·재계산, 새로운 순위·성과·경험·조건을 만들지 않도록 지시한다.
- 원문에서 대조할 수 있는 근거 문구를 연결하고 일부 금액·날짜·수업량 패턴을 대조한다. 없는 수치·근거·개인 연락처가 발견되면 보류한다.
- 이런 형식 검사가 의미상 모든 사실을 검증하는 것은 아니다. 실제 학교 공식 정보와 최신 조건을 사람이 확인해야 한다.
- 사진·이미지 속 정보는 입력에 포함되지 않는다. 관련 주의점과 검토 메모는 관리 화면에만 표시하고 공개 본문에 자동으로 섞지 않는다.
- 검색·AI 인용은 보장되지 않는다. 글 길이·FAQ 개수나 특별한 AI 마크업을 노출 비법으로 강제하지 않는다.

## 매시간 감지 설정

Cloudflare Pages Functions에 크론을 직접 설치하지 않았으므로 별도 Worker가 필요하다. 소스는 `workers/naver-scheduler/index.js`, 설정은 같은 폴더의 `wrangler.jsonc`다.

1. Cloudflare Worker `uksinchon-naver-sync`를 생성한다. 제공한 코드 또는 해당 폴더를 배포한다.
2. 관리자 화면에서 만든 예약 감지용 키를 **Pages와 Worker 양쪽**의 Secret `CMS_NAVER_CRON_TOKEN`에 동일하게 저장한다. 초기 관리자 설정키와 별도 키이며 채팅·공개 코드에 넣지 않는다.
3. Worker 예약 트리거는 `0 * * * *`다. 매시간 실행하며 Cron 기준은 UTC다. 관리 화면의 실행 시각은 한국시간으로 표시한다.
4. Pages 설정을 바꾸면 최신 버전으로 재배포하고 Worker도 배포한다.
5. 네이버 가져오기 화면에서 감지 허용을 켠다. 실제 **예약 호출** 시각·최근 확인 시각·오류·새 초안을 확인한다. Secret 설정 존재만으로 작동 완료로 보고하지 않는다.

예약 Worker는 고정된 신촌점의 `/api/cms/naver/cron`에 인증된 수집 요청만 보낸다. 공개 HTTP 호출은 404로 응답하며 공개 승인 API를 호출하지 않는다. Pages는 별도 예약 키·HTTPS·DB·관리자 초기 설정·감지 허용 여부를 검증한다. 일시 중지는 ‘새 글 감지 허용’을 끄고 저장한다. 이미 진행 중인 요청이 즉시 취소되는 기능은 아니다.

이 작업에서 Worker 생성·Secret 설정·실제 Cron Trigger 실행은 하지 않았다. 현재 환경에는 운영 Cloudflare 계정의 API 권한이 없으며 사용자 계정에서 설정해야 한다. API 키·예약 키 값을 대화로 받을 필요는 없다.

## 검수와 보존 규칙

- 네이버 글번호를 고유 키로 사용한다. 추적 쿼리와 모바일 주소를 정규화해 같은 글을 중복 생성하지 않는다. 다른 블로그나 임의 URL은 받지 않는다.
- 연결 전 기준 목록의 과거 글은 RSS가 수정되더라도 자동으로 신규 글로 바꾸지 않는다. 직접 선택해 가져온 글은 별도 작업한다.
- 같은 확인·재편집의 동시 실행은 임대 잠금과 SQL 조건부 갱신으로 제한한다. 사람이 AI 생성 중 초안을 수정하면 결과가 그 수정을 덮어쓰지 못한다.
- 원문 변경 시 검수 기록을 무효화한다. 기존 초안과 공개본은 자동으로 덮어쓰지 않는다. 필요하면 새 버전으로 재편집하고 검수한다.
- 검수는 **현재 저장 버전 + 현재 원문 해시**에 묶인다. 초안 수정·원문 변경 뒤에는 검수를 다시 기록해야 한다.
- 자동 추출 원문은 검수 기록 직전에 다시 읽는다. 변경되었거나 읽지 못하면 그대로 검수 완료로 처리하지 않는다. 수동 입력은 담당자의 전체 원문 대조 확인을 사용한다.
- 공개 API에서도 검수 일치 여부를 다시 확인하며 SQL 갱신 시점에 검수·원문 해시·확인 작업 진행 여부를 대조한다. UI 체크만 숨기거나 예약 키만 알아도 공개할 수 있는 구조가 아니다.
- 바탕이 된 네이버 원문 주소를 출처에 유지해야 공개할 수 있다. 네이버 글을 모두 학교 ‘공식 자료’라고 부르지 않도록 공개 글의 출처 제목을 ‘출처·참고 자료’로 정리했다.
- 원문 수정이 RSS에 반영되지 않는 경우를 실시간으로 감지한다고 보장하지 않는다. 검수 시 재확인과 개별 원문 다시 읽기를 사용한다.
- RSS 최근 범위를 벗어난 글이나 점검 공백 중 RSS에서 사라진 글은 놓칠 수 있다. 개별 URL 입력으로 보완한다. 과거 글 전체 수집 기능이 아니다.

## DB와 코드 위치

기존 CMS와 같은 `CMS_DB` D1을 사용한다. 관리자 메뉴를 처음 열거나 인증된 예약 확인을 시작할 때 새 테이블을 `CREATE TABLE IF NOT EXISTS`로 추가한다. 기존 사용자·게시물 테이블은 삭제하거나 새로 만들지 않는다.

- `cms_naver_source`: 감지 설정·기준 시점·마지막 확인/예약 호출·잠금
- `cms_naver_items`: 원문 주소·글번호·RSS 요약·원문 텍스트/해시·사진 참조·처리 상태·초안 ID·AI 모델/지침 버전·검토 메모·검수 기록
- `cms_naver_history`: 원문 해시별 텍스트·추출 방법·사진 참조·수집일
- 초안과 공개본: 기존 `cms_posts`·`cms_versions`·`published_revision` 구조 유지

편집 지침 버전은 `naver-editorial-v1`이다. 원문 안의 문구는 데이터이며 실행 지시로 따르지 않는다. AI에 웹 검색·도구 실행 권한을 주지 않는다. 원문 자체의 악성 HTML을 편집 화면에서 실행하거나 외부 사진을 그대로 삽입하지 않는다.

## 검증과 미구현

실제 네이버에서는 RSS·표본 본문의 읽기·추출만 확인했다. 실제 OpenAI API 요청이나 운영 사이트 공개는 하지 않았다.

가상 네이버·AI 응답을 실제 Workers/로컬 D1 실행기에 연결해 통합 검증 12개가 통과했다. 초기 기준 목록·중복·AI 미연결 대기·인증된 Cron·검수 차단·수정 후 검수 무효·원문 변경·AI 수치/근거 오류·동시 수정·불완전 원문·수동 초안·오류 자동 재요청 방지·중지 기능을 확인했다. Chromium 화면 검증 5개도 통과했다. 기존 CMS 통합 14개·화면 9개도 다시 통과했다.

```bash
python3 scripts/prepare_cms_dev.py
node tests/check_naver.mjs
# 화면 검증용 가상 서버를 별도 터미널에서 유지:
CMS_NAVER_UI_FIXTURE=1 node tests/check_naver.mjs
python3 tests/check_naver_browser.py
```

테스트는 `/tmp/uksinchon-cms-tools`의 Miniflare·esbuild를 사용하며 `CMS_TOOLING_DIR`로 별도 도구 폴더를 지정할 수 있다. 네이버·AI 네트워크 응답은 격리된 대역이며 운영 키나 실제 청구를 사용하지 않는다. 테스트 서버·가상 계정·설정은 운영 배포가 아니다.

현재 미구현: 사진 자동 이전·OCR·영상 처리·네이버 전체 과거 글 수집·실제 AI 품질 평가 완료·담당 직원 배정 UI·메일/카카오톡 검수 알림·멀티 모델 제공자 전환. 실제 정기 실행·운영 API 인증은 계정 설정 후 별도 검증한다.
