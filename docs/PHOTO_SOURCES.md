# 사진 출처를 선택 텍스트로 입력

확인일: **2026-11-18 한국시간** · 관련 로드맵: **R03(직원 입력), R04(공개 출력), R06(검증·배포)**

사용자 요청에 따라 사진 출처의 웹주소를 완성하지 않아도 업로드·저장·발행할 수 있게 변경했다. 기준 코드는 `557dd7a`, 구현·검증 커밋은 **`eca6d0f` (R03/R04/R06)**다. 기존 직원 직접 발행 기능을 유지한다.

## 확인한 동작과 변경

- `cms/server/api.js`: 사진 파일 업로드는 자체 WebP·크기·글 소유권을 검사하며 출처 주소를 받지 않는다. 파일 업로드 API는 변경하지 않았다.
- `admin/editorial.js`: 사진 출처 입력이 `type=url`이었다. 이를 일반 텍스트로 바꾸고 표시를 **사진 출처 · 선택 (주소 또는 설명)**으로 바꿨다.
- `cms/server/content.js`: 저장 모델은 이미 출처 설명이나 불완전한 주소를 보존했으나 `imageReadiness`가 발행 단계에서 유효한 URL을 요구했다. 사진 출처에 대한 이 제한만 제거했다.
- `renderDelta`: 완전한 HTTP(S) 주소는 기존처럼 **사진 출처** 링크로 표시한다. 일부 주소·설명은 **사진 출처: 입력 내용**으로 표시하고 HTML을 이스케이프한다. 빈 값이면 출처 표시를 생략한다. 입력 내용을 추측해서 URL로 완성하지 않는다.
- `admin/help.html`, `docs/STAFF_BLOG.md`: 선택 입력과 표시 방식을 안내한다.

예: 빈 값, `학교 홍보팀 제공`, `www.example.org/photos`, `https://`는 모두 저장·발행을 허용한다. 실행용 스킴이나 HTML 형태의 값도 링크·실행 코드로 해석하지 않는다. 유효한 주소만 `safeLink`를 거쳐 클릭 가능하게 한다.

자료 출처 전반의 검증을 없애는 대안은 공식 근거·표 링크의 기존 규칙까지 바꾸므로 채택하지 않았다. 사진 출처에 한정한 최소 수정을 적용했다. 장식용 사진의 대표 사진 금지, 실제 이미지 소유권·파일 검사, 공식 자료의 URL 및 필요한 현재 버전 사실 확인, 직원 본인 글 권한은 유지한다.

## 데이터와 복구

기존 `imageMeta[id].source` 필드를 사용하고 길이 제한 2,000자와 기존 주소 정규화를 유지한다. URL·slug·이미지 저장 위치·원고 버전·발행/수정 날짜를 바꾸거나 운영 원고를 일괄 재저장하지 않는다. DB 변환·마이그레이션·리디렉션은 필요하지 않다. 입력한 출처를 원고 JSON 보관/복구에서도 같은 필드로 유지한다.

코드 커밋을 되돌려 입력/발행 제한을 복구할 수 있다. 다만 변경 후 자유 텍스트 출처로 발행한 원고는 예전 제한으로 돌아가면 다음 재발행 때 주소 수정이나 지우기가 필요할 수 있다. 기존 원고의 텍스트를 일괄 삭제하지 않는다.

## 검증 기준

- 모델: 빈 값·설명·미완성 주소를 저장하고 발행 준비 검사를 통과한다. 완전한 주소만 링크로 표시하고 HTML/실행 스킴은 안전한 글자로 출력한다. 공식 자료·표·대표 사진 규칙은 유지한다.
- 실제 격리 Worker+D1: 직원이 일부 주소를 가진 사진을 업로드·저장·발행하고 공개 HTML에 링크가 아닌 글자로 표시한다. 수정·공개 내리기·소유권·역할 회귀를 함께 확인한다.
- Chromium: 텍스트 입력의 형식 제한 없이 일부 주소를 입력해 저장·미리보기·직접 발행한다. 미리보기와 공개 글에 같은 출처가 표시된다. 모바일·PC의 본문·편집기와 수정본 발행을 확인한다.
